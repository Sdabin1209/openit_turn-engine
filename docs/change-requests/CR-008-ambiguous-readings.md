# CR-008 규칙 해석이 갈리는 곳 확인 요청

- 대상: `answer_judge.md`, `dialogue_planner.md`
- 상태: 결정함(아래 "결정" 절)

## Judge

1. 선행 불충족 판정과 값 판정이 한 슬롯에 함께 생기면(같은 슬롯에 일부 항목만 선행 불충족), 선행 불충족 판정은 버린다(규칙 3 "합칠 때 빼고 본다"의 해석).
2. 확인 응답이 확인 대기 확인을 기다릴 때는 `confirmation`을 `NONE`으로 두고 판정(상태 없음)으로만 낸다. 종료·중단·정정 구체화를 기다릴 때만 `YES`/`NO`.
3. 발화 결과: 판정이나 확인 응답이 있으면 `HAS_ANSWER`, 요청·값 없는 정정·위험 신호만이면 `REQUEST_ONLY`(위험 신호 단독도), 무관이 있으면 `OUT_OF_SCOPE_ONLY`, 아무것도 이해하지 못했거나 항목이 없으면 `UNRECOGNIZED_TURN`.
4. 문항 전체 모름·거절의 확인 대기 버림 대상은 "남은 슬롯"의 확인 대기이며, 남은 슬롯은 같은 문항에 슬롯 판정(누락·선행 불충족 포함)이 없는 슬롯이다.
5. 빈 값(`value: null`)의 `CORRECTION_MARKED`가 대상이 정의에 없거나 선행 불충족이면 무관이다.

## Planner

1. 열린 문항: 필수 슬롯이 없는 문항("선택 문항")은 모든 슬롯이 비어 있을 때만 열린다.
2. 중단 확인 우선: 열린 요청.중단 요청이 예이면 "지금 물을 것"(묻지 않는 행동 뒤의 기다리는 답, 세션 시작·재개)은 항상 중단 확인이다. 규칙 7~19가 직접 내는 묻기는 이 우선을 받지 않는다(문서의 규칙별 문장을 따름). 중단 확인의 물은 횟수가 상한이면 중단 요청을 아니요로 하고 계속한다.
3. 물은 횟수·확인 횟수는 그 묻기가 실제 응답 행동일 때만 센다(무관 안내·대기 안내 뒤의 기다리는 답은 세지 않는다).
4. 종료 확인의 도움 요청: 물은 횟수가 상한과 같아질 때 한 번 `STAFF_NOTICE`+알림, 그 뒤는 알림 없이 종료 확인을 계속 묻는다(규칙 14의 "알림은 한 번"과 같은 방식).
5. 규칙 17의 "나중에": 요청의 대상 문항(Judge가 정함)이 열려 있으면 그 문항을 미룸에 더하고 다음 열린 문항을 묻는다.
6. 선행 조건이 맞지 않게 된 문항은 무효화된 문항처럼 시도 횟수와 건너뜀을 지운다(저장 결과 요약의 무효화에는 기록 없는 문항이 안 잡혀서).
7. 규칙 18에서 물음 상한으로 미룸에서 빠진 확인 대기는 보통의 남은 확인 대기로 취급해 규칙 16으로 바로 묻는다.
8. 안내 요청의 `REMAINING_COUNT`는 열린 문항(미룬 문항 포함, 건너뛴 문항 제외)의 수다.

## 결정 (헤드 답변 + 골든 대조, 2026-10-15)

골든으로 확정된 것(a/골든 일치):
- Judge 판정의 `said_value`는 애매(UNCLEAR) 판정에만 담는다. 정상·정정 등은 `null`(골든 69건).
- Judge 판정 순서는 발화 항목의 순서(그 대상이 처음 나온 항목)이고 누락 판정은 맨 뒤(골든 S6a, S7a, S8b, X1, N17).
- 충돌의 `CREATE`는 `target_pending_ids`를 비운다. 대체되는 이전 확인 대기는 저장 판단이 기록에서 안다(골든 N6).
- 발화 결과: 값 없는 정정만, 위험 신호만이어도 `HAS_ANSWER`(골든 C5, G1). `REQUEST_ONLY`는 진행 조작·안내·사람 요청만 있을 때.
- MISMATCH를 단 항목(양쪽)은 표준 값 없음, 비교 `NOT_APPLICABLE`(골든 S2b, S6a, B4).
- Planner: 행동 뒤에 이어 묻는 것(`awaiting`)도 물은 횟수·확인 횟수를 센다(골든 G8b, H3d, H3e, R7). 재개·세션 시작도 센다. 반복 요청의 재생은 세지 않는다.
- Planner: 반복 키가 있는 선택 문항은 한 반복 키에 답이 있으면 닫힌다. 선행 조건이 맞지 않게 된 문항도 시도 횟수를 지우지 않는다(요약에 잡힌 무효화만 지운다; 골든 S1b, S2b).
- Planner: 확인 상한에 닿으면 이미 확인 중단 목록에 있어도 같은 처리(중단 추가+기존 답 유지 알림; 골든 N6, C8a).

골든이 가려 주지 못했거나 예시와 어긋나 남은 해석(잠정):
1. 확인 응답이 확인 대기 확인을 기다릴 때 `confirmation`은 `NONE`(골든은 이 입력 형태에서 `UtteranceJudgment`만 보여 줌, 판정이 정함).
2. 선행 불충족 판정과 값 판정이 한 슬롯에 함께 오면 선행 불충족을 버린다.
3. Planner: 중단 요청 우선은 "지금 물을 것"(묻지 않는 행동 뒤의 기다리는 답)에만 적용한다.
4. 규칙 17의 "나중에": 요청의 대상 문항이 열려 있으면 그 문항을 미룸에 더하고 다음 문항을 묻는다.
5. 규칙 18에서 물음 상한으로 미룸에서 빠진 확인 대기는 규칙 16으로 바로 묻는다.
6. 선택 문항(필수 슬롯 없음)은 모든 슬롯이 비었을 때만 열린다.
7. Judge 판정 순서: 선행 불충족 확인 항목의 위치(골든 S6c와 다름, b).
