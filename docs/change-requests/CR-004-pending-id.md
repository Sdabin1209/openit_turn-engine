# CR-004 확인 대기 ID를 결정적으로 만드는 방법

- 대상: `docs/rules/record_writer.md` 7절 규칙 3("확인 대기 ID는 확인 대기 둠마다 새로 만든다"), `RecordWriterInput`
- 상태: 요청

## 부족한 것

라이브러리는 난수·시간을 쓰면 안 되고 같은 입력은 같은 출력을 내야 한다. 그런데 "새로 만든다"를 하려면 호출마다 다른 값이 필요하다. 입력(`RecordWriterInput`)에는 턴 번호도 ID 후보도 없다.

## 지금 구현(임시 해석)

`pnd-` + (슬롯, 새 값, 대체되는 이전 확인 대기 ID, 현재 값)의 SHA-256 앞 20자(`writer.new_pending_id`). 결정적이다. 약점: 같은 슬롯에서 같은 값이 같은 현재 값과 충돌해 버려진 뒤 또 오면 같은 ID가 나온다. 이전 확인에 대한 "네"가 새 값을 받아들이면 안 된다는 규칙 취지는, 버려진 ID가 확인 대기 목록에서 사라지므로 지켜지지만 ID 재사용 자체는 막지 못한다.

## 제안

`RecordWriterInput`에 선택 필드 `pending_id_seed`(문자열; 호출자가 턴마다 유일한 값을 주입)를 추가하고 해시에 넣기. 또는 `new_pending_ids: [PendingId]`를 호출자가 주입. MINOR 추가다.
