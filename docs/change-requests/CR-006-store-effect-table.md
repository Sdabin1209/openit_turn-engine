# CR-006 저장소 효과표(9-2절)가 규칙 문서에 없음

- 대상: v1 규칙 문서 record_writer 7절(보관) 규칙 1("9-2절 표대로 확인 대기를 그대로 두므로"), `StoreAction`
- 상태: 결정함(아래 "결정" 절)

## 부족한 것

규칙 1은 9-2절의 표를 인용하지만 전달된 문서에 9-2절(저장소가 각 `StoreAction`에 어떻게 반영하는가)이 없다. 다음을 가정해 구현했다. 틀리면 바로 고쳐야 한다.

- `FIRST_WRITE`: 기록이 없는 슬롯의 첫 답. 모름·거절 기록이 있던 슬롯에 답이 오면 `NEW_REVISION`(이전 값 없음, 요약의 종류는 `FIRST_ANSWER`).
- `ACCEPT_PENDING`: 확인 대기의 값을 새 revision으로 쓰고 확인 대기를 지운다. 판정이 "정정(받아들임)"일 때 `NEW_REVISION` 대신 이것 하나만 낸다. 확인 응답만의 받아들임도 같다.
- `NEW_REVISION`, `RECORD_UNKNOWN`, `RECORD_REFUSAL`은 확인 대기를 지우지 않는다(규칙 1에 적힌 대로). `FIRST_WRITE`가 확인 대기를 지우는지는 모른다.
- `INVALIDATE`: 슬롯의 현재 값과 확인 대기를 함께 지운다.
- 이미 같은 모름·거절 기록이 있는 슬롯에 모름·거절이 또 오면 결정을 내지 않는다("변경 없는 슬롯은 내지 않는다").

## 제안

9-2절을 규칙 문서에 전달하거나, 위 가정을 확인해 주기.

## 결정 (헤드 답변 + 골든 StoreResult 대조, 2026-10-15)

StoreAction 의미는 원본에서 확인되어 가정과 일치한다. 골든 214쌍과 대조해 고친 것(a):

- 모름·거절 기록이 있던 슬롯에 답이 오면 `NEW_REVISION`이 아니라 `FIRST_WRITE`(골든 S8d, X7). 요약의 종류는 `FIRST_ANSWER`.
- 문항 전체 모름·거절: 슬롯마다 기록 결정을 낸 뒤, 확인 대기가 있는 슬롯의 `DROP_PENDING`을 모아 그 뒤에 둔다(골든 R13, N17, X2). 판정이 가리킨 ID가 아니라 각 슬롯의 확인 대기를 버린다.
- 무효화: 문항의 슬롯 순서(`question_slots`)로 낸다. `INVALIDATE`의 `pending_id`는 비운다(골든 S6c).
- 확인 대기를 둘 때 `ACCEPT_PENDING` 하나로 새 revision+대기 지움은 골든 N17에서 확인됨(정정 받아들임).

골든이 가려 주지 못한 것(남음): `FIRST_WRITE`가 확인 대기를 지우는가. 골든에 해당 조합이 없다. 이 항목과 "9-2절 효과표 원문"은 헤드가 사용자에게 올린다.
골든의 예시 오류(c): R13·X2의 `RECORD_UNKNOWN`에 대기 ID가 붙어 있음, S8b의 `FIRST_WRITE`에 ID가 붙고 결정 순서가 판정 순서와 다름.
