# CR-003 위험 문구(`risk_phrases`)와 `utterance` 사용 규칙

- 대상: `AnswerJudgeInput.utterance`, `AnswerJudgeInput.risk_phrases`, `docs/rules/answer_judge.md`
- 상태: 요청. **이 부분은 구현하지 않았다.**

## 부족한 것

Judge 입력에는 발화 원문과 세션 설정의 위험 문구 목록이 있지만, 규칙 문서에는 이를 쓰는 규칙이 없다. 다음이 정해져야 구현할 수 있다.

1. 문구와 발화를 어떻게 맞추는가(부분 문자열? 공백·조사 무시?).
2. 맞으면 모델이 위험 신호 항목을 내지 않았어도 `risk_signal`을 만드는가(모델 누락을 코드가 보완하는 안전망인가).
3. 근거(`evidence`)로 무엇을 담는가(맞은 문구, 발화 일부).
4. 발화 원문은 개인정보라 로그에 남기지 않는다는 제약과의 관계.

## 지금 구현

위험 신호는 `RISK_SIGNAL` 의도 항목에서만 만든다. 위험 문구 목록과 발화 원문은 읽지 않는다. 즉 모델이 위험 신호를 놓치면 이 라이브러리는 잡지 못한다. 환자 안전과 닿으므로 우선 답이 필요하다.

## 제안

- 안전망으로 쓰는 것이 의도라면 "발화에 위험 문구가 공백을 뺀 부분 문자열로 들어 있으면 `risk_signal.evidence`에 그 문구를 담는다"처럼 한 문장으로 정하기.
