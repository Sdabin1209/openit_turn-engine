# 0007. 학습 데이터 A 전수 시험은 환경 변수 TURN_ENGINE_DATASET_A가 있을 때만 돈다

- 상태: 수용(재실행 기록은 0.4.0에서 없음, 점검 TE-4)
- 관련: `tests/test_validation.py`(skipif), `scripts/validate_dataset_a.py` / `docs/runbook.md` / `docs/STATUS.md`

## 맥락

`validate_extraction`이 실제 학습 데이터 A(LoRA-A 출력)를 위반 없이 통과시키는지는 규칙이 데이터와 맞는지 보는 가장 직접적인 시험이다(0.3.0에서 5,077행 위반 0). 데이터는 학습 서버에 있고 이 리포지토리에 없다.

## 결정

시험 `test_validation.py`의 전수 검사는 환경 변수 `TURN_ENGINE_DATASET_A`(JSONL 경로, `:`로 구분)가 있을 때만 실행하고 없으면 건너뛴다. 서버의 데이터를 읽는 명령(`scripts/validate_dataset_a.py`는 표준입력으로 받는다)은 runbook에만 있고 기본 시험에 넣지 않는다.

## 왜

- 데이터를 리포지토리에 두지 않는다. 학습 서버는 읽기 전용으로만 탐색한다는 사용자 규칙이 있고(학습 서버 접속은 이 영역의 기본 시험 경로가 아니다), 데이터 크기·소유도 이 영역이 아니다. 경로를 외부에서 주는 옵션이 가장 단순하다. (이 단락은 코드의 skip 사유와 `validate_dataset_a.py`의 사용법, 워크스페이스 규칙에서 읽은 추론이다.)
- 기본 시험은 네트워크 없이 어디서나 돌아야 한다(Docker·GPU·서버 불필요, README 4절).

## 검토한 대안과 버리는 이유

근거 기록 없음(대안을 비교한 문서를 찾지 못했다). 생각할 수 있는 대안과 현재의 약점만 적는다(제안, 미확정).

| 대안 | 상태 |
|---|---|
| 데이터 일부 표본을 리포에 포함 | 시도 기록 없음. 환자 데이터는 아니나 소유와 크기 판단이 필요하다. 미정 |
| 건너뛰면 실패로 취급하는 CI 모드 | 기록 없음 |

## 결과

- 약점: 기본 실행에서 이 시험이 건너뛰어져 "전체 통과"가 데이터 적합성까지 보장하지 않는다(점검 H3, TE-4). 0.4.0 변경 뒤 전수 시험을 다시 돌린 기록이 없다(`STATUS.md`).
- 완화: 건너뛴 사유가 출력된다(`pytest -rs`). 데이터를 쓰는 변경(규칙 해석 변경)은 runbook 절차로 전수 검증한 뒤 CHANGELOG에 기록하는 것이 점검의 권고다.

## 되돌리는 조건

전수 검증을 릴리스 전 필수 절차로 바꾸면 옵션이 아니라 릴리스 체크리스트로 승격한다. 학습 데이터 정본 위치(D77, D78: 학습 서버)가 바뀌면 runbook 명령을 고친다.
