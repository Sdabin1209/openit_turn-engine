# 0003. 순수 함수이고 I/O가 없는 설계

- 상태: 수용
- 관련: `docs/boundary.md` 2절·4절 / `docs/design.md` / D46, D80

## 맥락

검증 결과는 합성 데이터 생성, 모델 평가, 출고 게이트, 서비스 런타임이 모두 쓴다. 이들이 서로 다른 시점·장소에서 같은 판정을 내야 한다.

## 결정

`validate_extraction`은 입력만으로 결과가 정해지는 순수 함수다. 모델 호출, 저장소, 네트워크, 파일 I/O, 시간, 난수, 전역 설정을 쓰지 않고 입력을 바꾸지 않는다. 입력을 로그로 남기지 않으며 오류 메시지에 입력 값을 싣지 않는다. 런타임 의존은 `jsonschema`와 boundary-contracts(태그 고정, ADR 0006)뿐이다("무의존"이 아니라 "I/O 없음, 의존 최소"다).

## 왜

- 재현성: 합성 데이터·평가·게이트가 "같은 버전이면 같은 결과"를 전제로 버전을 기록한다. 시간·난수·설정이 끼면 이 전제가 깨진다. 같은 이유로 출력이 달라지는 변경은 MINOR로 올린다(`boundary.md` 4절). D46·D80이 서비스와 게이트의 버전 일치를 요구하는 근거도 이것이다.
- 개인정보: 환자 발화가 입력에 들어 있다. 로그·메시지에 값을 싣지 않으면 이 라이브러리가 유출 경로가 되지 않는다. 저장·전송 코드가 없다는 것이 가장 단순한 보장이다.
- 시험 용이성: 이웃 영역 없이 혼자 시험된다(메모리 구현이 필요 없다, `boundary.md` 1절). 시계·네트워크·무작위가 없어 간헐 실패 시험이 생기지 않는다(점검 H2).
- 의존이 적을수록 소비자 이미지의 공급망 표면이 작다(다만 점검 TE-2가 `jsonschema>=4.18` 범위 지정과 해시 없는 잠금을 지적했다. 미해결).

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 설정 파일·환경 변수로 규칙 조정 | 같은 버전이 다른 결과를 낼 수 있다. 규칙 변경은 코드 변경과 버전 상승으로만 한다 |
| 위반을 로그/메트릭으로 직접 남김 | I/O가 생기고 입력 값 유출 위험이 있다. 기록은 호출자(survey-service)가 위반 코드만 남기는 쪽이 낫다 |

근거 기록: 위 대안을 직접 비교한 문서는 찾지 못했다. 위 이유는 `boundary.md`의 약속(순수·결정적, 입력 불변, 개인정보)과 버전 부여 방식에서 읽은 것이다.

## 결과

- 얻는 것: 결정적 출력, 안전한 동시 호출(전역 상태 없음), 로그 유출 없음.
- 감수하는 것: 위반의 운영 관찰(지표·로그)을 이 라이브러리가 하지 않으므로 호출자가 맡아야 한다. 점검 E1·E2는 N/A로 판정했다.

## 되돌리는 조건

규칙이 실행 중 외부 정보(예: 문진 스키마를 직접 읽기)를 필요로 하게 되면 파일 읽기를 넣지 말고 표를 인자로 받는 지금 모양(`QuestionFlowTable`)을 유지한다. I/O가 필요해지는 요구가 확정되면 별도 ADR로 이 결정을 대체한다.
