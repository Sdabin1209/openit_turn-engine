# 0005. v1 함수(normalize, judge, write_record, plan)를 0.4.0에서 제거한다

- 상태: 수용(G07 닫힘, 커밋 23973fc, 태그 v0.4.0)
- 관련: D74, D75(3), D76(2), `head/docs/OPEN_GAPS.md` G07 / `docs/CHANGELOG.md` 0.4.0

## 맥락

D74(2026-10-27)로 정규화·절차·다음 문항 결정이 LoRA-A로 옮겨 가 서비스에 정규화기·Plan 코드를 두지 않게 됐다. 0.3.0은 이 함수들을 지우지 않고 `DeprecationWarning`만 붙였다(survey-service가 아직 쓰고 있었기 때문. 제거 시점은 survey-service 이전이 끝난 뒤라는 헤드 지시).

## 결정

survey-service 이전이 끝난 뒤 0.4.0에서 `normalize`, `judge`, `write_record`, `plan`, `OutputContractError`, `SUPPORTED_RUNTIME_CONTRACT_VERSION`, 해당 모듈, 문진 스키마 사본(`turn_engine/_schemas/`), 골든과 v1 시험·예시를 제거한다. 공개 API는 7개(`validate_extraction`, `Violation`, `QuestionFlowTable`, `SkipRule`, `DATASET_V2_FLOW`, `ENGINE_VERSION`, `ContractViolation`)로 줄인다. 깨지는 변경이지만 0.x라서 MINOR 자리를 올린다.

## 왜

- D74 근거: v1은 가능한 상황을 코드로 다 만들어야 해서 경우의 수 대응이 문제였다. 모델이 그 일을 하게 되었으므로 코드가 남아 있으면 두 곳이 같은 일을 하며 어긋난다.
- 폐기 표시만 남기면 죽은 코드가 시험·의존·문서 부담으로 남고, 이웃이 "아직 써도 된다"고 오해할 수 있다. 제거 전에 이웃 8개 리포에서 import·호출이 없음을 grep으로 확인했다(`CHANGELOG.md` 0.4.0).
- 문진 스키마 사본(`_schemas/`)은 "복사본을 만들지 않는다"는 규칙(D19, 계약 패키지 안 스키마 사용)에도 어긋나 같이 없앴다.
- 이력은 git(태그 v0.3.1 이전 커밋)에 남아 있으므로 설계 기록은 잃지 않는다(`design.md`).

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 폐기 표시를 영구 유지 | 위 이유(죽은 코드·오해). 폐기 표시는 이전 기간 한정이었다 |
| 즉시 제거(0.3.0에서) | survey-service가 이전 전까지 호출 중이었다(D76: 2단계가 뒤따름) |
| v1 모듈을 별도 패키지로 분리 | 사용할 소비자가 없다. 근거 기록: 이 대안을 검토한 문서는 찾지 못했다 |

## 결과

- 얻는 것: 코드·시험·의존 대폭 감소(시험 수가 0.3.x보다 크게 줄었다, `STATUS.md`), 공개 API가 일곱 개로 분명해짐.
- 감수하는 것: v1 골든 868쌍 같은 자료를 git 이력에서만 볼 수 있다. 0.3.x 이하를 쓰는 소비자는 업그레이드할 수 없다(없음을 grep으로 확인).

## 되돌리는 조건

v1식 서비스 쪽 판정이 다시 필요해지면(예: LoRA-A를 쓰지 않는 구조로 복귀) git 이력의 v0.3.1 이전 커밋에서 복원하지 말고 새 ADR로 요구를 다시 정한다.
