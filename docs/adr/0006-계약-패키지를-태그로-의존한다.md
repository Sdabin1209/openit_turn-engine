# 0006. boundary-contracts를 Git 태그로 고정해 의존한다 (스키마 복사본 없음)

- 상태: 수용
- 관련: D18, D22, D26, D46, `boundary-contracts` ADR 0002 / `pyproject.toml`, `requirements.lock` / `docs/CHANGELOG.md` 0.3.0·0.3.1·0.4.0

## 맥락

`validate_extraction`은 입력과 출력을 `ActionExtractionInput`, `ActionExtraction` 스키마로 먼저 검증한다. 이 스키마의 정본은 boundary-contracts다.

## 결정

boundary-contracts를 Git 태그(현재 `v2.0.2`)로 설치해 `boundary_contracts.validator(...)`로만 스키마를 쓴다. 스키마 복사본을 만들지 않는다. 태그는 `pyproject.toml`과 `requirements.lock`에 고정하고, 의존 태그를 확인하는 시험이 있다.

## 왜

- 워크스페이스 규칙: 스키마는 패키지에 들어 있으므로 `load_schema`, `validator`를 쓰고 복사본을 만들지 않는다. 0.2.x까지는 스키마 사본이 있었고 0.4.0에서 지웠다(ADR 0005).
- 사본은 계약 버전이 올라갈 때 조용히 어긋난다. 태그를 올리는 것이 의존 변경의 유일한 경로이면 변경이 diff로 보인다(0.3.1은 v2.0.1로 올리려고 낸 PATCH였다: 다른 영역이 v2.0.1과 같이 쓰려면 새 turn-engine 버전이 필요했기 때문).
- 태그 고정이 "범위 지정"보다 낫다는 이유: 게이트가 승인한 동작이 서비스에서 달라지지 않게 하려고 버전을 정확히 맞추는 것이 이 프로젝트의 정책이다(D46, D80). 의존이 뜻하지 않게 올라가면 같은 turn-engine 버전에서 결과가 달라진다.
- Git 태그 배포 자체의 이유는 D18(패키지 인덱스 서버를 두지 않음)과 `boundary-contracts` ADR 0002를 따른다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 스키마를 turn-engine에 복사 | 위 이유(어긋남, 복사 금지 규칙) |
| 버전 범위(`>=2.0`) | 같은 turn-engine 버전의 재현성이 깨진다. 단 `jsonschema`는 현재 범위 지정(`>=4.18`)이고 점검 TE-2가 지적했다(미해결) |

## 결과

계약 변경 시 turn-engine은 반드시 PATCH 이상의 새 릴리스를 내야 한다. 이는 약점이 아니라 의도다. 감수하는 것: 설치에 GitHub SSH 키가 필요하다(README 4절). 잠금 파일은 태그만 고정하고 커밋 해시는 주석으로만 둔다(점검 TE-2, 개선 대기).

## 되돌리는 조건

계약 패키지가 레지스트리로 옮겨 가면(`boundary-contracts` ADR 0002의 되돌리는 조건) 설치 줄만 바꾸고 고정 정책은 유지한다.
