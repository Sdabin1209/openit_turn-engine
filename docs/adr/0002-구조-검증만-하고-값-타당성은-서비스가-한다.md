# 0002. validate_extraction은 구조(의미 규칙)만 검증하고 값의 타당성은 서비스가 한다

- 상태: 수용. 단, 경계의 범위 한계는 열린 항목이다(아래 TE-1)
- 관련: D74, D75(3), `boundary-contracts/INTERFACES.md` I8 / `docs/boundary.md` 8-1 / 점검 `head/docs/audit/model-runtime-turn-engine.md` TE-1

## 맥락

LoRA-A는 환자 발화에서 값을 뽑아 `ActionExtraction`(values, targets, action, next_item 등)을 낸다. 모델은 가끔 틀린다. 의료 문진 기록에 틀린 값이 들어가는 것보다 다시 묻는 편이 안전하다(D75-1). 검증을 어디까지, 누가 해야 하는가.

## 결정

검증을 세 층으로 나누고 turn-engine은 가운데 층만 맡는다.

1. 형식(JSON 스키마): model-runtime. 끝내 못 지키면 503 `OUTPUT_INVALID`(I9).
2. 의미 규칙(스키마로 표현할 수 없는 구조 규칙): turn-engine `validate_extraction`. `targets`가 `values` 키의 부분집합, `next_item` 규칙, 건너뛰기 순서, `save` 규칙. 위반 목록을 돌려준다.
3. 값의 타당성(칸별 타입·열거·범위, 중복 키, 다른 문항 덮어쓰기): 이 라이브러리의 범위 밖. 서비스가 문진 스키마로 한다(현재 서비스가 어디까지 하는지는 이 영역에서 확인하지 못했다).

## 왜

- 스키마로 표현되지 않는 규칙을 모델 서버의 제약 디코딩에 맡길 수 없다: vLLM 구조화 출력이 `allOf`·`if/then`·`not`을 조용히 무시한다(D48). 그래서 조건 규칙은 사후 검증이 맡는다(D48, D82, D83).
- turn-engine은 문진 스키마를 읽지 않는다(0.4.0부터). 칸의 타입·열거·범위는 문진 스키마(survey-service 소유, D19·D21)에 있고, 문항 순서·건너뛰기 표의 소유도 survey-service다(D76). 타당성 검사를 turn-engine에 넣으려면 turn-engine이 문진 스키마를 소유자 허락 없이 복제하거나 읽어야 한다. 한 사실을 아는 영역이 한 곳에서만 쓴다는 워크스페이스 규칙과 맞지 않는다.
- 호출 쪽은 위반이 있으면 `OUTPUT_INVALID`와 같게 처리한다(재시도 한 번, 그래도 안 되면 턴 실패 신호, 세션 상태 불변, D75-1). 즉 틀린 값을 만들어 채우지 않는다.

## 검토한 대안과 버리는 이유

| 대안 | 버리는 이유 |
|---|---|
| 의미 검증도 model-runtime의 스키마에서 | 제약 디코딩이 조건 키워드를 못 지킨다(D48). 사후 검증이 어차피 필요하다 |
| 모든 검증(값 타당성 포함)을 turn-engine에서 | 문진 스키마 소유 경계를 넘는다. `QuestionFlowTable`을 문진 스키마에서 만드는 변환조차 아직 없다(CR-010, 소유는 survey-service로 정함 D76) |
| 검증 생략하고 모델을 신뢰 | 모델은 가끔 틀린다는 전제(D75-1)에 반한다 |

## 결과

- 얻는 것: 책임 경계가 분명하다. 순수 함수라 결정적이고 시험이 쉽다. 학습 데이터 A 5,077행 전수 위반 0(0.3.0 시점 기록).
- 감수하는 것(TE-1): 점검에서 실행으로 확인한 통과 사례가 있다. `Q4.bogus=123456789`, `Q4.answer="열대여섯"`, Q4 질문 중 `Q1.D01.*` 저장, 같은 키 중복(마지막 값이 이김)이 위반이 아니다. 현재 문서가 약속한 규칙과는 일치하므로 버그가 아니라 범위의 한계다.

## 되돌리는 조건

TE-1은 "I8 규칙 확장"으로 `UNKNOWN_SLOT`, `DUPLICATE_KEY` 위반과 칸별 타입 표를 추가하는 안이 점검에 제안돼 있다. 계약 변경이며 MINOR 버전이다. 헤드 결정 대기이고 확정된 것이 아니다(결정 기록 없음). 서비스가 값 타당성을 이미 검증하는지 확인되면 이 ADR의 3층 설명을 사실에 맞게 고친다.
